# Vylino Lead Ingestion Production Endpoint

## Route

Expose a server-side POST route such as:

`/api/vylino/leads/ingest`

The browser must never receive CRM, Redis, n8n, or Twenty API credentials.

## Authentication

The endpoint expects the header:

`x-vylino-ingest-key: <server-side shared secret>`

Store the secret in server configuration, for example:

`VYLINO_LEAD_INGEST_SECRET`

Do not commit the secret to source control or inject it into public JavaScript.

## Request body

The request body is the existing `WordPressLeadWebhookRequest` generated by the WordPress/Elementor integration layer.

Required high-level fields:

- `event: "lead.submitted"`
- `sentAt`
- `idempotencyKey`
- `payload`

## Production idempotency

Use `RedisLeadIngestionIdempotencyStore` with Twenty's existing `RedisClientService.getClient()` connection.

Claim behavior:

- key: `vylino:lead-ingestion:<idempotency-key>`
- claim value: `pending`
- claim uses atomic Redis `SET ... EX ... NX`
- default pending TTL: 15 minutes
- successful CRM persistence changes the marker to `completed`
- completed markers are retained for 7 days by default
- failed CRM persistence releases only a `pending` claim

This prevents concurrent duplicate form requests from creating multiple CRM opportunities.

## Processing order

1. Validate HTTP method.
2. Authenticate the shared-secret header.
3. Validate the webhook envelope.
4. Atomically claim the idempotency key in Redis.
5. Persist Company / Person / Opportunity in Twenty.
6. Mark the Redis claim completed.
7. Emit `lead.created` or `lead.updated` to n8n.
8. Return the persistence and automation-delivery result.

CRM persistence remains the primary transaction. A temporary n8n failure must not cause CRM records or opportunities to be created twice.

## Twenty server integration

Twenty currently exposes Redis through `RedisClientService.getClient()` and organizes HTTP endpoints as Nest controllers/modules. A thin Nest controller can therefore adapt `Request` into `handleVylinoLeadIngestionHttpRequest`, using:

- `TwentyCoreApiTransport` for CRM access,
- `createTwentyRedisLeadIngestionStore(redisClientService)` for Redis,
- `VylinoN8nAdapter` for automation delivery.

The route should remain server-side and explicitly guarded/authenticated even when exposed as a webhook-style public endpoint.
